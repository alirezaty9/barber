# banad barber — سامانه‌ی رزرو نوبت آرایشگاه (فول‌استک)

اپلیکیشن رزرو آنلاین نوبت آرایشگاه با **Next.js (App Router) + JavaScript** (بدون TypeScript)، **Tailwind CSS v4**، **Prisma + PostgreSQL**، پرداخت آنلاین زرین‌پال، احراز هویت ادمین، و تقویم شمسی.

## امکانات
- صفحه‌ی فرود با کاتالوگ خدمات/آرایشگران/نظرات از دیتابیس.
- ویزارد رزرو ۴ مرحله‌ای با **تقویم شمسی** و بررسی **تداخل و مدت‌زمان خدمت** سمت سرور.
- **کد رهگیری** برای مشتری + صفحه‌ی `/track` برای مشاهده‌ی نوبت‌ها.
- **لغو نوبت توسط مشتری** با کد تأیید پیامکی — پشتِ کلیدِ `NEXT_PUBLIC_SMS_ENABLED` و فعلاً خاموش (رجوع به `src/lib/features.js`).
- **پرداخت آنلاین زرین‌پال** + آزادسازیِ خودکارِ اسلاتِ رزروهای پرداخت‌نشده.
- پنل مدیریت محافظت‌شده: داشبورد، مدیریت نوبت‌ها (فیلتر/جست‌وجو/صفحه‌بندی)، ثبت نوبت دستی، و CRUD کامل خدمات و آرایشگران.
- احراز هویت ادمین با رمز عبور + کوکی امضاشده (JWT) و محافظت با middleware.
- داده‌ی سرور با **TanStack Query**، state کلاینت با **Zustand**، فرم‌ها با **React Hook Form + Zod**.
- UX دسترس‌پذیر: مودال Radix (focus-trap/Esc/قفل اسکرول)، Toast (sonner) به‌جای alert، دیالوگ تایید به‌جای confirm.

## پیش‌نیاز
- Node.js نسخه‌ی ۱۸.۱۸ یا بالاتر

## راه‌اندازی
```bash
# ۱) نصب وابستگی‌ها (postinstall به‌صورت خودکار prisma generate را اجرا می‌کند)
npm install

# ۲) ساخت فایل env
cp .env.example .env
#   سپس مقادیر ADMIN_PASSWORD و SESSION_SECRET را در .env تنظیم کن.

# ۳) ساخت دیتابیس و دادهٔ اولیه
npm run db:push        # ساخت جداول از روی prisma/schema.prisma
npm run db:index       # ایندکسِ یکتای ضدِ رزروِ تکراری (حتماً لازم است)
npm run db:seed        # ریختن داده‌های اولیه

# ۴) اجرا
npm run dev            # http://localhost:3000
```

ورود به پنل: به `/admin/login` برو و رمز `ADMIN_PASSWORD` را وارد کن.

## بیلد پروداکشن
```bash
npm run build
npm run start
```

## دیپلوی روی لیارا (Liara)

> ⚠️ این پروژه **پوشه‌ی `prisma/migrations/` ندارد** و عمداً با روشِ `db push` کار می‌کند
> (یعنی جدول‌ها مستقیم از روی `prisma/schema.prisma` ساخته می‌شوند، بدون تاریخچه‌ی مهاجرت).
> پس دستور `prisma migrate deploy` اینجا **هیچ کاری نمی‌کند** و بدونِ خطا رد می‌شود —
> از آن استفاده نکن، وگرنه فکر می‌کنی جدول‌ها ساخته شده‌اند در حالی که دیتابیس خالی است.

پیکربندیِ استقرار در فایلِ `liara.json` ریشه‌ی پروژه است: پلتفرم `next`، پورت `3000`،
تایم‌زونِ کانتینر `Asia/Tehran`، و یک Cron Job روزانه برای باطل‌کردنِ رزروهای رهاشده.

**۱) دیتابیس.** در پنلِ لیارا یک دیتابیسِ **PostgreSQL** بساز. افزونه‌های PostGIS و Pgvector
را **خاموش** بگذار (این پروژه نه فیلدِ جغرافیایی دارد نه بردارِ معنایی). دیتابیس را در یک
**شبکه‌ی خصوصی** بگذار و نامش را یادداشت کن — برنامه هم باید در همان شبکه ساخته شود.

> 🔑 **قاعده‌ی دو آدرس — مهم‌ترین نکته‌ی این بخش.** دیتابیس دو آدرس دارد و هرکدام جای خودش:
>
> | آدرس | کجا | چه زمانی |
> |---|---|---|
> | **عمومی** | `.env` روی کامپیوترِ خودت | فقط موقعِ `db:push` / `db:index` / `db:seed` |
> | **خصوصی (داخلی)** | متغیرهای برنامه در پنلِ لیارا | همیشه |
>
> برای اجرای دستورهای مرحله‌ی ۲ باید «دسترسی از شبکه‌ی عمومی» را موقتاً **روشن** کنی،
> چون کامپیوترِ تو داخلِ شبکه‌ی خصوصیِ لیارا نیست. **بعد از راه‌اندازی دوباره خاموشش کن**؛
> یک دیتابیسِ بازِ روی اینترنت شبانه‌روز اسکن می‌شود و این دیتابیس نام و موبایلِ همه‌ی
> مشتری‌ها را دارد. هیچ بخشی از خودِ سایت به دسترسیِ عمومی نیاز ندارد — فقط اسکریپت‌های
> دستیِ `prisma/*.js` که از کامپیوترِ خودت اجرا می‌شوند.
>
> ⚠️ اگر اشتباهاً آدرسِ **عمومی** را در متغیرهای برنامه بگذاری، اول کار می‌کند ولی لحظه‌ای
> که دسترسیِ عمومی را ببندی کلِ سایت می‌خوابد.

هر دو متغیرِ `DATABASE_URL` و `DIRECT_URL` یک مقدار می‌گیرند — اینجا اتصال مستقیم است و
تفکیکِ Pooled/Direct لازم نیست.

**۲) ساخت جدول‌ها.** با همان مقادیر در محیط، یک‌بار از روی سیستمِ خودت اجرا کن:

```bash
npm run db:push        # ساخت جدول‌ها
npm run db:index       # ایندکسِ یکتای ضدِ رزروِ تکراری (حیاتی)
npm run db:seed        # داده‌ی اولیه (خدمات و آرایشگر)
```

> `db:index` شاملِ **ایندکسِ یکتای شرطی** است — تنها ضمانتِ واقعی در برابر رزروِ هم‌زمانِ
> یک ساعت توسط دو نفر. اگر ترجیح می‌دهی دستی بزنی، محتوای `prisma/sql/indexes.sql` را
> در کنسولِ SQL دیتابیسِ لیارا پیست و اجرا کن. همه‌ی دستورهایش `IF NOT EXISTS` دارند،
> پس اجرای دوباره‌شان بی‌خطر است.

**۳) متغیرهای محیطی.** در پنلِ لیارا → برنامه → `تنظیمات` → `متغیرهای محیطی`، همه‌ی
کلیدهای `.env.example` را وارد کن. مواردی که روی پروداکشن حتماً باید فرق کنند:

| متغیر | مقدار پروداکشن | چرا |
|---|---|---|
| `ALLOW_MOCK_PAYMENT` | `false` | وگرنه رزرو بدون پرداخت واقعی ممکن می‌شود |
| `ZARINPAL_SANDBOX` | `true` تا گرفتن مرچنت واقعی، بعد `false` | تا پول واقعاً جابه‌جا شود |
| `NEXT_PUBLIC_BASE_URL` | آدرس کامل دامنه، بدون `/` انتهایی | **اجباری** — بدون آن sitemap و بازگشت از درگاه می‌شکنند |
| `SESSION_SECRET` | یک رشته‌ی تصادفیِ **جدید** | کلیدِ لوکال و پروداکشن باید جدا باشند |
| `ADMIN_PASSWORD` | رمزِ قوی | صفحه‌ی `/admin/login` روی اینترنتِ عمومی است |
| `CRON_SECRET` | رشته‌ی تصادفیِ بلند | تا فقط کرونِ خودِ لیارا بتواند مسیرهای `/api/cron/*` را بزند |

> 🔴 **متغیرها را در `liara.json` نگذار.** فیلدِ `envs` در آن فایل وجود دارد، ولی
> (الف) رمزها را داخلِ گیت می‌برد و (ب) هر بار استقرار، **همه‌ی** متغیرهای قبلیِ پنل را
> با محتوای فایل جایگزین می‌کند. همیشه از پنل واردشان کن.

> ⚠️ هر متغیری که با `NEXT_PUBLIC_` شروع می‌شود **موقعِ بیلد** داخلِ کد جا می‌افتد.
> عوض‌کردنش بدونِ استقرارِ دوباره هیچ اثری ندارد.

**۴) استقرار.** با CLI لیارا از ریشه‌ی پروژه:

```bash
npm i -g @liara/cli    # یک‌بار
liara login            # یک‌بار
liara deploy --app <نام-برنامه>
```

**۵) انتقال داده‌ی لوکال (اختیاری).** اگر خدمات/آرایشگران را روی دیتابیسِ لوکال ساخته‌ای:

```bash
TARGET_DATABASE_URL="<liara-postgres-url>" node prisma/sync-to-remote.js
```

⚠️ این اسکریپت **اول مقصد را پاک می‌کند** و بعد داده‌ی مبدأ را می‌ریزد. فقط روی دیتابیسِ تازه اجرا کن.

**۶) بررسیِ Cron.** بعد از اولین استقرار، در پنلِ لیارا لاگِ برنامه را ببین. اگر کرون
پاسخِ `401` گرفت، یعنی متغیرِ `$CRON_SECRET` داخلِ دستورِ کرون جا نیفتاده. در آن صورت
در `liara.json` دستور را به شکلِ زیر عوض کن (رمز به‌جای هدر، در آدرس):

```
0 3 * * * curl -fsS "http://localhost:3000/api/cron/expire-pending?secret=$CRON_SECRET"
```

و اگر باز هم جا نیفتاد، همان رمز را مستقیم در آدرس بنویس — ولی آن‌وقت `liara.json` رمز
دارد، پس باید از گیت خارجش کنی.

⚠️ این اسکریپت **اول مقصد را پاک می‌کند** و بعد داده‌ی مبدأ را می‌ریزد. روی دیتابیسی که داده‌ی واقعی دارد اجرا نکن.

